# Frontend (`apps/web`)

- React 19 + Vite + React Router (`react-router`, not `react-router-dom`).
- Styles: colocated CSS Modules (`.module.scss`). Do not add Tailwind or a second styling system.
- Domain types and form validation come from `@fleet-live/shared`. Do not re-declare vehicle schemas. `src/types/` is table generics (`table.ts`), not domain models.
- User-facing copy is German.

## Data

- HTTP only through `src/api/` (`client.ts` + resource modules). Components do not `fetch`.
- List state lives in the URL (`useVehicleListQuery`). Cache, prefetch, and SSE focus stay in hooks (`useVehicleList`, `useVehicleStream`).
- Live updates: existing EventSource + focus POST. Do not add polling or WebSockets.
- Handle loading, error, and not-found explicitly (see `VehicleDetailPage`).

## UI split

- `components/ui` stays generic (Table, Button, Modal, Avatar, Checkbox, Input). No vehicle fields there. Use those primitives everywhere (assignment, fleet picker, tables, login, registration, account, forms). Do not add raw `<input type="text|search|checkbox">` or one-off initial circles.
- Vehicle columns/filters belong in `components/vehicles/` (e.g. `vehicleTableConfig.tsx`). Alert columns/filters belong in `components/alerts/`. Driver columns belong in `components/drivers/`. Deadline columns belong in `components/due/`. The shift briefing lives on `/` (`BriefingPage`). The deadline list lives on `/fristen` (`DuePage`). Speed colour comes only from `speedBand` / `SPEED_BAND_COLORS`, not status greens.
- Prefer composition and local state. No new global store; `VehiclesProvider` already coordinates list epoch and telemetry overrides. Write actions (create/edit/delete, sim pause, resolve alerts, driver assignment, depot CRUD) are for `dispatcher`; `viewer` is read-only (including inbox, drivers, speed indicator, depot circles).
- Web tests: Vitest + Testing Library in `apps/web/src/test/` (`npm run test:web`). Do not add a second test runner.

## Map

- Leaflet on the detail page (`VehicleMap`) and the fleet page (`FleetMap`); shared basemap/theme in `leafletMap.ts`.
- Marker at last telemetry. The detail-map trail is the **selected** trip: the open trip plus live `path_delta` while `DRIVING` and that open trip is selected; a selected closed trip draws its archived polyline (no live append). Decode with `decodePolyline`. SSE `path_delta` is road vertices, not the tick chord. `path_reset` replaces the trail (new trip), it does not append. Do not concatenate a closed `trip.path` with live crumbs. The trip table is paginated; list rows have no `path` — fetch `GET …/trips/:tripId` for the line.
- A vehicle reports every few seconds (about 5 s, irregular); the marker slides along the new vertices at the speed that fits the time of the last ping (`useMarkerSlide`), so it is always one ping behind and never jumps. The trail grows with the marker, never ahead of it. The map stays centered on the vehicle until the user pans or zooms; "Fahrzeug zentrieren" resumes follow and keeps it.
- Status is not a form field and not a trip toggle.
- Do not fetch the telemetry history for the trail. That is the hot buffer and it rolls over mid-drive.
- No map on the list page. It shows only the current page and exposes the telemetry batching.
- Fleet map: markers and clusters, no trails. Snapshot via `GET /api/vehicles/positions` once per non-status filter or `drivers` change — pan, zoom, and plate search do not refetch. Plate or current-driver search lists matches from that snapshot; choosing one centers the map, opens the side panel and moves the focus to the plate there, the status chip stays, and the other vehicles stay. A hit outside the chip is still drawn. Empty driver selection means the company snapshot, not “no markers”. Rows with `has_position: false` are not drawn. A KPI band above the map (`FleetKpiBand`) holds six tiles. The four status tiles (Auf Fahrt, Standby, Feierabend, Kein Signal) filter that snapshot in the client and replace the fleet-map legend; each shows Y large and `X im Ausschnitt` as the hint. Y counts the filtered fleet with a position, so the four Y values sum to that count. Tempo jetzt (`counts.speeding` from the briefing, server filter `speeding`) and Wenig Tank (`counts.low_fuel`, filter `low_fuel`) toggle server filters. Warnungen, Kein Fahrer, and Im Depot stay server filters in the toolbar and combine with the status tile. Wenig Tank is only the tile (no second chip for the same filter). Above `FLEET_POSITIONS_MAX` Y is the sum of density-cell `counts`, the status tiles are disabled, and a status does not hide vehicles inside a mixed cell. A depot strip (`DepotStrip`) under the map lists `GET /api/sites` with `in_depot_count` / `home_count`; `DepotPanel` only shows while a depot is selected, placed or edited. A second click on the selected depot (circle or list), its „Auswahl aufheben“ button or Escape clears the selection and the `depot` URL parameter; an unsaved edit blocks that. Escape on the map closes the innermost thing first (vehicle panel, placement, depot); dialogs, menus and the help drawer take Escape before the page. The right sidebar (360 px) holds the selected vehicle and „Live-Ereignisse“ (`FleetEventFeed`): the newest 25 alerts of all states, type chips only for types with rows, refetched on `listEpoch` (`vehicles-changed`), no polling. A row selects the vehicle if it is in the snapshot, else opens its detail page. `meta.without_position` is shown only when it is greater than 0; in positions mode that count opens the list of those vehicles. Grouping is switched off for now (test): every vehicle in view is its own dot (`clusters` in `FleetMap`); the cluster code below stays for when it comes back. Points cluster locally through zoom 14 (`FLEET_CLUSTER_MAX_ZOOM`). Zoom 15 (scale bar about 200 m) draws the individual markers; the smallest groups used to open only at 17 (50 m), which was too close. The basemap may scale past its native tiles up to zoom 18. When a group opens, its members get a thin ring in `--text-h` (`markerStyle(…, grouped)`; not yellow: around a 4 px dot a yellow ring reads as the dot's colour, and yellow is Standby), because the flight can open the neighbouring groups too and the ring shows which dots belong to the clicked one; it ends when the user zooms out half a level past where the group was, or opens another group. The index rebuilds when the vehicle set changes and at most about once a second when only coordinates change, built from the positions the vehicles are shown at (`PositionTweens`), not from their last reports. Opened without `bbox` (nav, Schicht), the map frames the whole fleet once it has loaded (quarter zoom steps). A cluster click flies as close as all its members still fit in the view (at least to the zoom where it splits), framed on their live positions with 500 m around each driving member (the sim runs in time-lapse). A selected vehicle is never part of a group (always its own dot with the yellow ring); while it drives the map pans with it over the same time its dot glides, until the user drags, wheels, double-clicks or uses the zoom buttons; clicking its dot again resumes. Place names show from zoom 10 (`LABEL_MIN_ZOOM`) and hide while a zoom loads, so no scaled-up old names shine through. The route lines are hidden from zoom 13, where the tiles draw the streets. Supercluster uses `extent: 256` so the 60 px radius is 60 screen pixels; the cluster level is the zoom rounded down. Where a vehicle is shown comes from one place, `PositionTweens` (`components/vehicles/positionTween.ts`): each report starts a stretch from the position shown now along the road points that came with it (`path_delta`, decoded relative to the last report; a `path_reset` far away jumps) to the report, over a smoothed average of that vehicle's last gaps times 1.25, so irregular pings still look even and the vehicle is one report behind, like any tracker; a gap over 20 s (a missed report) or reduced motion jumps. Dots are drawn at that position every frame, the group index is built from it (membership only), a group symbol rides every frame at the middle of its members' shown positions (`PositionTweens.centre`) and eases out the small shift when a rebuild changes its members, and the follow camera pans to the position the dot is heading to over the same stretch. Do not give dots, groups or the camera their own timers. Dots do not move while the map zooms (`zoomstart`…`zoomend`): Leaflet keeps the canvas at the old scale and stretches it, so a dot moved mid-zoom showed beside the road; they jump to their place when the zoom ends. A click on a vehicle (dot, selected symbol or a row of the map list) flies to it at zoom 11 (scale bar 3 km) or keeps a closer zoom (`VEHICLE_CLICK_ZOOM`); follow pans wait for the flight. Dots and group symbols are `SmoothDot` / `SmoothMarker` (`smoothMarkers.ts`): Leaflet rounds markers to whole pixels, which at regional zoom (under a pixel of motion per second) made vehicles tick once every few seconds; these keep the fraction. When a zoom splits or merges groups nothing is swapped in one frame (`TRANSITION_MS`): a new group or a dot that comes out of a group starts at the old symbol's place and eases to its own (groups also fade in); a group or dot that goes away stays for the same time, slides towards the group (or dot) that now holds its vehicles and fades (`Leaving`). Depot names give way to vehicles: a name that touches a group symbol or a vehicle dot is hidden. Vehicles piled within 25 m also open the member list. Tiles do not load while zooming (`updateWhenZooming: false`, `keepBuffer: 4`), so a flight keeps the old tiles instead of going black; the route lines step out while a zoom moves a whole level or more and come back when it ends, instead of being scaled into a wide band. The list stays until the user zooms back out or closes it. Cluster icons are keyed by the lowest vehicle id in the group (`anchor`), not by the Supercluster id, which changes on every rebuild (the symbol would be replaced and jump instead of gliding); a click reads the group's current id from its record. The ring shows status counts; Kein Signal marks the cluster. Density mode above `FLEET_POSITIONS_MAX` draws cells, not a sample, and then has no per-vehicle rows for the without-position list. The side list is the bottom-left panel and only appears when the current view has at most 100 vehicles, so it never sits under Depots as a truncated dump of the company. The Fahrer control is a modal (`Modal` `size="lg"`) that searches drivers (one vehicle each, show plate) and applies with Übernehmen — not a dropdown, not a roster dump, not a status chip. The toolbar shows a summary on the trigger (name or count), never selected names as filter chips; add/remove only in the modal. Search shows the real match `total` and paginates (`page`); do not present `FLEET_DRIVERS_LIST_LIMIT` as the hit count. SSE focus is every `DRIVING` id of the loaded snapshot (not only the current view), the selected one first, capped at `STREAM_FOCUS_MAX_IDS`: vehicles inside a group or just outside the view keep moving, so none arrives with an old position when the view changes. A streamed report older than a reloaded row never overwrites it (`applyVehicleOverrides` compares `recorded_at`). A marker or list row selects the vehicle in the sidebar panel beside the map (plate, driver, status, speed, age of `recorded_at`, link to the detail page) and highlights that row. The panel does not cover the map. „Alle Fahrzeuge anzeigen“ fits the filtered fleet. The toolbar shows Live from the SSE connection (`connected` and `event: heartbeat`); `letzte Änderung vor X s` is only the age of the last patch. A dropped stream shows a fixed notice. Draw with a Leaflet canvas renderer — do not create thousands of DOM marker icons. Company depots are named circles (`GET /api/sites`); dispatcher edits them in `DepotPanel` (place, drag, radius). `Input` covers search and range sliders; do not add a raw `<input type="range">`.
- `components/ui` stays map-free.

## Domain copy

- Status labels live in `components/vehicles/vehicleStatus.ts`. Do not render the raw enum.
- Tempo in the list/detail uses `speedBand` from shared and `SPEED_BAND_COLORS` — not `VEHICLE_STATUS_COLORS`. Orange is over `speed_limit_kmh` without an open event; red is `speeding_open`. Inbox `/alerts` is warnings (Ereignis from `formatAlertEvent`, chips for open/resolved and `type`); `/drivers` is SPEEDING history (snapshot driver). Vehicle detail lists open LOW_FUEL / OFFLINE. `/` is the company shift briefing: title, KPI tiles, then charts. Deadline counts are three tiles and open `/fristen` in that state (`overdue`, `soon`, `missing`). A long row list is not the first block on that page. Tiles and charts deep-link into vehicles, drivers, inbox, and lists. A count of a warning type opens the inbox with that type (`/alerts?type=…`, so Wenig Tank and the „Kein Signal“ chip), not the vehicles; Kein Signal as a vehicle status tile opens the vehicle list. The Warnungen nav shows the open inbox count. Fristen is in the nav without a badge.
- `/fristen` (`DueBoard`) groups rows by kind in this order: Führerschein, HU, UVV, Führerscheinkontrolle. State tiles (overdue / soon / missing) switch `state` and keep `kind`. The overview loads each kind (limit 25) and `allocateDueRows` hands rows out so the list fills its measured height; kinds without rows share one line. A kind filter shows that kind with pagination. Each row shows a consequence pill from `dueConsequence`. The rail shows each kind's rule (`dueRuleText`) and the company settings (`DueSettingsFields`). A legal basis appears only when `dueRule(kind).verified` is true.
- Vehicle detail (`VehicleDetailPage`) fits the window from 1001 px: left column Jetzt, Hinweise (open OFFLINE / LOW_FUEL plus overdue or missing HU/UVV), Stammdaten with a compact driver line; right column the map and the trip list sharing the height, the trip list scrolls in its panel with the pagination visible. Fahrzeug löschen sits in the „Weitere Aktionen“ menu (`VehicleMoreMenu`); the driver roster with all assignment actions opens in a modal. The detail map has no status legend.
- `/drivers` is a list page (`DriverTable`, no board and no `?ansicht` view): tiles Alle, Gespräch führen (`min_open_warnings` = `DRIVER_TALK_MIN_OPEN_WARNINGS`), Ohne Fahrzeug (`without_vehicle`), with the numbers from `meta.counts`; exactly one is pressed and the URL carries the filter. Columns Fahrer (bold text, no link, no avatar), Telefon, Fahrzeug, Verstöße, Davon offen; a row click opens `/drivers/:id`. „Auswählen“ (dispatcher) offers „N löschen“ through the confirm dialog: each driver is deleted on its own, a `409` (driver is on a trip) stays in the dialog with the API message and that driver stays selected. Page size follows the measured rows. Driver detail (`DriverDetailPage`) uses the vehicle layout: header with „← Fahrer“, open-warnings pill, Bearbeiten and „Weitere Aktionen“ (Fahrer löschen, same dialog); left Jetzt, Hinweise (licence expiry, licence check, phone: missing or overdue, „Eintragen“ opens the edit form), Stammdaten; right Tempo-Warnungen (`GET /api/alerts?driver_id`, five rows, Erledigen for dispatchers) and Fahrzeuge (the assignment roster with all its actions).
- `/konto` uses a side navigation; the section is the URL hash (`#passwort`, `#zwei-faktor`, `#team`, `#firmen-login`, `#firmen`). Team and Firmen-Login are dispatcher only; an unknown or forbidden hash falls back to Passwort. Firmen lists the person's companies with a switch button and the form for a new company.
- List pages use the frame in `components/ui/ListPage` (`ListPage`, `ListPageHeader`, `ListPanel`, `ListToolbar`, `SelectionBar`, `ListBody`, `ListFooter`, `ListEmpty`) with `ui/KpiTiles` as the main filter (also behind `FleetKpiBand`), `ui/Menu/MenuButton` for further filters and export, `hooks/useSelectionMode` for „Auswählen“ and `hooks/useListPageSize` for the measured page size (`limit` 1–100 for `/api/vehicles`). `/vehicles` is on it: tiles Alle, Auf Fahrt, Standby, Feierabend, Kein Signal, Tempo jetzt, Mit Warnung, Wenig Tank (the four status tiles add up to Alle; a filter from „Weitere Filter“ replaces the tile filter, then no tile is pressed and the toolbar button shows it); Kein Fahrer and Im Depot under „Weitere Filter“; bulk delete in selection mode with the plates in the confirm dialog.
- Inbox (`/alerts`) is a list page (`rules/design-system.md`): tiles Offen, Tempo, Funk, Wenig Tank, Erledigt are the filter (Wenig Tank is the same set of vehicles as on the vehicle pages; its rows have no Erledigen and are not selectable, they close when the tank is filled) (the type tiles always count open warnings, so Erledigt keeps their last open numbers); no search; rows are plate plus driver, Art, Ereignis, Zeitpunkt and the row button Erledigen (open rows, dispatchers). Page size follows the measured rows. Selection is a mode ("Auswählen", not on the Erledigt tile): a row click toggles, row buttons are hidden, the selection bar offers "N erledigen" through a confirm dialog on `PATCH /api/alerts` (`ids`). Selection resets on page, filter or sort change. Single and bulk resolve show a short `role="status"` line in the header.
- Phones (≤ 700 px, signed in): the header is one 52 px bar (menu button, section title, help, live dot). The menu opens a drawer with identity, all pages, the Warnungen badge, the sim toggle (dispatcher) and Abmelden. Table cards put the label above the value in a grid.
- Help: the „?“ button opens `HelpDrawer` with the text for the current route (`help/helpContent.ts`); answers about dispatcher actions are hidden for viewers. One-time tips (`PageTips`, `help/tipCatalog.ts`) anchor to `data-tip` on Schicht and Fristen. The shift page title row shows `FirstSteps` for dispatchers (import, depot, deadline lead, team, two-factor; each from a real signal) until all are done or it is hidden; it is hidden while the import prompt shows. Hidden and seen flags live in localStorage per user and company (`utils/localFlags.ts`).
- Timestamps from the API are naive UTC. Format them via `utils/dateTime.ts`, never print the raw string.
