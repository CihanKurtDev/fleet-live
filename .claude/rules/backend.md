# Backend (`apps/api`)

```
app.ts + routes → Controllers → Models → SQLite
```

- `app.ts` and `routes/` only wire HTTP to controllers (stream and sim live in `app.ts`, vehicles, alerts, drivers, briefing, due, sites, and auth in `routes/`).
- Auth: register does not set a session until the e-mail is confirmed. Password reset and login rate limits apply outside tests. `company_memberships` holds role and company; the session stores the active company. Invites, TOTP and OIDC live under `/api/auth`. Second factor: only a login step issued for setting one up (`enroll`, account without a factor) may choose a secret (`POST /totp/setup` with `challenge`, otherwise `403`); a step that asks for the existing factor checks against the stored secret only. Wrong codes: 5 per login step (then the step is used up), 10 per account in 15 minutes (`429` `TOTP_RATE_LIMITED`, `lib/totpAttempts.ts`, in memory). A code counts once: `users.totp_last_step` holds the last accepted time step. Sessions: the cookie holds the token, the `sessions` table only its sha256 (`lib/tokenHash.ts`, column still `token`). An idle session (no "remember me") ends 15 minutes after its last use; the end moves at most once a minute, and expired rows are swept once a minute (`SessionModel.purgeExpiredIfDue`), but an expired row is never accepted either way. Passwords: scrypt with N = 65,536 (1,024 in tests), stored with their own cost; sign-in and password change hash and verify asynchronously (`hashPasswordAsync`, `verifyPasswordAsync`), a correct sign-in replaces a hash with a lower cost (`needsRehash`), and an unknown email spends the time of a check (`spendPasswordTime`). A company keeps at least one dispatcher. Empty companies ask once about `/vehicles/import` (`import_prompt`). Vehicle writes, `PATCH /api/sim`, `PATCH /api/alerts/:id`, `PATCH /api/alerts` (bulk), driver writes (including `DELETE /api/drivers/:id`), depot writes, `PATCH /api/due/settings`, and `GET /api/export/vehicles`, `/alerts`, `/trips`, `/period` use `requireDispatcher` after `requireAuth`.
- Controllers validate, map HTTP, call models, set status codes. No SQL.
- Models own SQL via `db/statements.ts` / `db/database.ts`. No `req`/`res`.

## Contract

- Validate with `@fleet-live/shared` (`validateVehicleInput`, `parseVehicleListQuery`, …).
- Throw `AppError` subclasses from `lib/errors.ts`. User-facing `error`/`fields` are German; `code` is English (`VALIDATION_ERROR`, `NOT_FOUND`, `CONFLICT`).
- Unique license plates are per company (`UNIQUE (company_id, license_plate)`).
- `GET /api/vehicles` returns `{ data, meta }`. `filter` includes `stopped` (status `STOPPED`, „Feierabend“; `meta.counts` has `stopped` and `speeding`, so driving + idle + stopped + offline = all), `unassigned` (no `current_driver_id`), `in_depot` (`depot_site_id` set) and `speeding` (an open SPEEDING event, the same condition as `speeding_open`). `GET /api/vehicles/positions` returns `{ data, meta }` of last-known positions (slim DTO, optional `bbox=west,south,east,north`, `drivers` names, and the same `filter` ids as the list). `search` is accepted and does not restrict rows. Rows include `has_position`; without telemetry, coordinates are null and `meta.without_position` counts them for the company (bbox does not apply to that count). `meta.matched` is the same filter without bbox, including rows without a position. Over `FLEET_POSITIONS_MAX` positioned matches the response is `density` (grid), not a sample. `GET /api/vehicles/drivers` returns `{ data: { name, license_plate }[], meta: { total, page, limit, pageCount } }` — search (`search`, `page`) plus optional `names` hydration. `total` is the match count, not the page size; it does not dump the roster. `GET /api/vehicles/:id/telemetry` and `GET /api/vehicles/:id/trips/latest` return `{ data }` (latest includes `path`). `GET /api/vehicles/:id/trips` returns `{ data, meta }` of slim rows without `path`. `GET /api/vehicles/:id/trips/:tripId` returns `{ data }` with `path`. Vehicle JSON is snake_case, including nested telemetry fields.
- A vehicle without a trip is `{ data: null }`, not a 404. Only a missing vehicle is a 404.
- `GET /api/alerts` returns `{ data, meta }` for the session company (`filter` open/resolved/all, optional `type` SPEEDING/LOW_FUEL/OFFLINE, optional `vehicle_id` / `driver_id`, `page`, `limit` as any whole number from 1 to `LIST_PAGE_LIMIT_MAX` (100, default 10; the list asks for as many rows as fit its measured height, anything else is `400`), `sort` created_at/type/severity/driver_name/license_plate with `dir`). Join includes `license_plate` and the snapshot `driver_id` / `driver_name`. Rows include `ended_at` and `details` (SPEEDING: `{ limit_kmh, max_speed_kmh, duration_s }`). `meta.counts` ignores `type`; `meta.type_counts` respects `filter`. Access is `alert → vehicle → company`. Other company’s `vehicle_id`, `driver_id`, or alert id is `404`. `PATCH /api/alerts/:id` with `{ resolved: true }` closes a row (`dispatcher`); a second close is idempotent. `PATCH /api/alerts` with `{ ids, resolved: true }` (1–`ALERT_BULK_MAX_IDS`, unique positive ints) closes several in one transaction (`dispatcher`); any id outside the session company is `404` and nothing changes; already resolved rows stay; the response is `{ data: { resolved } }` with the rows this call closed, and `vehicles-changed` goes out when it is above 0. Unresolved count remains `active_alerts` on the vehicle. `speeding_open` on the vehicle is an unfinished SPEEDING event (`ended_at` null), independent of `resolved_at`.
- `GET /api/drivers` returns `{ data, meta }` (search/page, `limit` as any whole number from 1 to `LIST_PAGE_LIMIT_MAX` (100, default 10; the list asks for as many rows as fit its measured height, anything else is `400`), optional `vehicle_id`, `min_open_warnings` (1–1000) and `without_vehicle=true` (no vehicle has this driver as current); `meta.total` follows the filters; `meta.counts` is `{ all, talk, without_vehicle }` for the page tiles (`talk` = open SPEEDING at `DRIVER_TALK_MIN_OPEN_WARNINGS` or more) and follows search and `vehicle_id` but not the tile filters; default sort `open_warnings` desc). Counts, `open_warnings` and `last_warning_at` (newest open one) are SPEEDING only (snapshot). `GET /api/drivers/:id` adds eligible vehicles and `current_vehicle`. Other company’s driver is `404`. `POST /api/drivers`, `PATCH /api/drivers/:id`, `DELETE /api/drivers/:id`, `POST /api/drivers/:id/vehicles`, `DELETE /api/drivers/:id/vehicles/:vehicleId`, and `PATCH /api/drivers/:id/current-vehicle` require `dispatcher`. `DELETE /api/drivers/:id` is `204`, or `409` while the driver is current on a `DRIVING` vehicle; one transaction clears current on vehicles, removes eligibility, sets `alerts.driver_id` to null (history stays) and deletes the driver. HTTP vehicle writes do not upsert drivers. `GET /api/vehicles/drivers` remains the fleet name picker.
- Vehicle create/update may include optional yard fields (`vin`, `vehicle_type`, `hu_due_on`, `depot`, `home_site_id`, `cost_center`); VIN is unique per company when set. `home_site_id` is the Stammstandort; `depot` is its denormalized name. A `depot` string that matches a site name sets `home_site_id`; an unknown name clears home and keeps the text. Import accepts the same columns plus optional driver `phone`.
- `GET /api/sites` returns `{ data }` of company depots (name, circle, `home_count` / `in_depot_count` / `other_home_count`). `POST`/`PATCH`/`DELETE /api/sites` require `dispatcher`. Unauthenticated is `401`. Other company’s site id is `404`.
- `GET /api/briefing` returns `{ data }` for the session company: `counts` (`open` inbox, `offline` / `driving` / `idle` vehicle status, `low_fuel` under threshold, `in_depot` last position inside a company circle, `speeding` vehicles with an open SPEEDING event), monthly `history` for the Schicht charts, and `due` counts only (no row list). A set calendar date is overdue or due within the company lead (`due_lead_days`, catalog default 30, at most 365); an empty HU/UVV/licence-expiry date is a missing count. A licence check is overdue when missing or older than the company interval (`licence_check_months`, catalog default 6, 0 = off). These are not alert types. `viewer` may read; no write on this route. Unauthenticated is `401`. Other companies’ rows are omitted.
- `GET /api/today` returns `{ data, meta }` for the Schicht task list: kinds in order `deadline_overdue`, `driver_talk`, `offline`, `low_fuel`, `deadline_soon`; `limit` 1–50 (default 12) rows shared across the kinds that have tasks; `meta.counts` per kind equals the list the chip opens (`/api/due?state=…`, open LOW_FUEL alerts (same vehicles as filter `low_fuel`), `/api/drivers?min_open_warnings=5`, open OFFLINE alerts). Viewer may read. Unauthenticated is `401`. `GET /api/sim/routes` returns the simulator roads as encoded polylines for the maps.
- `GET /api/due` returns `{ data, meta }` for the same rule, one row per date (`state` overdue/soon/missing, optional `kind`, `search` on the plate or driver name, page/limit). `meta.total` matches the briefing count when `kind` and `search` are empty. `meta.counts` follows the search and ignores `kind`. `meta.kind_counts` follows `state` and the search. A missing field is its own row. `viewer` may read. Unauthenticated is `401`.
- `POST /api/import/preview` accepts exactly one of `csv` (text) or `xlsx` (base64 of `.xlsx`). CSV is one vehicles table. Excel worksheets named Fahrzeuge / Fahrer / Eignung / Aktuell (or English equivalents) are classified; an unmatched first sheet is vehicles. Without a client mapping, a saved company profile overlays matching column headers (`profile_applied`). `POST /api/import/commit` runs in one transaction (drivers → vehicles → eligibility → current); a persist error rolls back and keeps the preview. Successful commit writes `import_runs` and, unless `save_profile` is false, upserts `import_mapping_profiles`. `GET`/`PUT /api/import/profile` and `GET /api/import/runs` are dispatcher-only and company-scoped. `GET /api/export/vehicles`, `/alerts`, `/trips` and `/period` return `text/csv` for the session company (semicolon, German headers, UTF-8 BOM). Dispatcher only. The vehicle file uses the import headers. The trip file has no path and adds liters from `FUEL_LITERS_PER_100KM` (25) times the driven kilometers. `/period` is one month (`month=JJJJ-MM`, default the current Berlin month): closed kilometers plus open trips started that month, warnings created that month split by whether they are resolved, and the same liters. The tank gauge does not change. A viewer gets `403`. Unauthenticated is `401`.

## Counts

- Every vehicle filter and count (status, `low_fuel`, `in_depot`, `speeding`, `alerts`, `unassigned`) is defined once as a predicate in `db/vehicleConcepts.ts` (`VEHICLE_CONCEPT_SQL`). The list and its facets, the map density cells and `GET /api/briefing` use it; do not write the condition again in another query. `countConsistency.test.ts` compares list, briefing and inbox on one database. `counts.stopped` (Feierabend) is part of the briefing; Schicht has no tile for it yet.
- `npm test` runs the files named in the `test` script of `apps/api/package.json`; `testRegistry.test.ts` fails when a file in `src/test` is not named there or two paths are glued together.

## Environment

- `NODE_ENV` has no default: `config.ts` stops the process when it is missing. The npm scripts of `apps/api` load `dev.env` (`--env-file`, tracked, no secrets): `NODE_ENV=development`, `ALLOW_DEMO_ACCOUNTS=true`. Demo accounts are created at start only with `ALLOW_DEMO_ACCOUNTS=true` outside production.
- JSON bodies: 16 kB (64 kB for `/api/stream/focus`) before the sign-in; `/api/import` reads up to 32 MB only after `requireDispatcher` (`routes/import.routes.ts`). A body that is not JSON is `400`, one over the limit `413` (`errorHandler`).

## SSE

- `GET /api/stream` + `POST /api/stream/focus` with `connection_id`.
- The simulator plays devices, so the app only ever sees what a real tracker would send: each `DRIVING` vehicle with a driver of a company that has not paused the sim sends one ping per `PING_INTERVAL_MS` (default 5000, each vehicle at its own 60–160 % of it, so the fleet does not report in one burst), whether or not anyone watches. `TELEMETRY_TICK_MS` (default 1000, 0 = simulator off) is only how often it looks for due pings (`TelemetryModel.tickDrivingVehicles`, `duePings`). The road covered by a ping follows from the real time since that vehicle's last ping (`elapsedS` in `nextSimTick`). A ping is one write: one telemetry row (rolling window), one path append, one fuel/limit update. Its `recorded_at` has milliseconds (`nowSqliteMs`); the map times its playback by it. Do not add a faster tick for animation; the map animates between pings, the same code that will run on real pings. Patches go only to connections that focused that id. After each tick the ticker also applies OFFLINE (15 s silence while that company is paused, or status `OFFLINE`), and depot presence (`SiteModel.applyPatches` sets `depot_site_id`; no inbox row). There is no live LOW_FUEL event in the ticker (the tick does not change `fuel_level`); the LOW_FUEL warning follows the tank where it is written (`ExceptionEventModel.syncFuel`, import commit, start-up): one open row under the threshold, closed when it is above it. `PATCH /api/alerts` does not close LOW_FUEL or OFFLINE rows (they follow their state; `exceptionEvents.test.ts` and `stateAlerts.test.ts` assert this). `vehicles-changed` goes only to connections of the same company. An SSE connection belongs to the session company; `POST /api/stream/focus` cannot bind another company's `connection_id`.
- A tick writes position, speed and the consumed `fuel_level`; the patch carries all of them.
- A viewer whose socket is full (`res.writableNeedDrain`) gets no growing queue: telemetry waits per vehicle in `Client.pending` (latest values, `path_delta` chunks appended, a `path_reset` drops what came before) and goes out as one merged event on `drain`. Small events (`vehicles-changed`) are written at once. The merge is exact because `path_delta` is a delta chain like `path = path || ?` (`test/hubBackpressure.test.ts`).
- The focus cap is `STREAM_FOCUS_MAX_IDS` (3,000; the schema, the hub and `TELEMETRY_BATCH_SIZE` follow it). A ping costs ~0.1 ms per vehicle on the dev DB. `/api/stream/focus` accepts a 64 kB body for it.
- `/api/stream` is compressed by the hub's own writer (`sse/compression.ts`: Brotli, else gzip, by `Accept-Encoding`), not by the general `compression` middleware, which buffers until the end and is excluded for this route. Every event is flushed at once (sync flush), so nothing is delayed; the dictionary lives across events. Hub and controller talk to an `SseWriter`, never to the compressor directly. The first write (`retry` + `connected`) is one chunk. On the dev data it takes 984 KB/s per viewer down to ~120 KB/s (Brotli) at the same data age, for about 1 % of a core per viewer. Do not replace SSE with WebSockets.

## Trips

- `syncTrip` in the vehicle controller owns the lifecycle: into `DRIVING` opens a trip, out of it appends a telemetry point with speed `0` (`recordStandstill`), closes the trip and returns the re-read vehicle.
- Each tick appends the road vertices of that step to the open trip (`TripModel.appendPoints`) inside the tick transaction. SSE may include `path_delta` (encoded suffix) so the map can grow the line without refetching. The first suffix of a new trip sets `path_reset`.
- Reaching a simulated route end closes the trip (status stays `DRIVING`). The way back is a new trip.
- At the start a vehicle that stands within 500 m of another (`spreadOnRoute`, e.g. many set to driving in one depot) goes to the middle of the widest free stretch on any sim road, in a fixed random direction; its old trip closes there and a new one opens (`relocated`), so no line jumps. Vehicles that stand alone keep their place, so a restart moves nobody twice.
- The path grows in SQL (`path = path || ?`). Do not load `trips.path` per tick; only `close` decodes it, once, to simplify.
- Closed trips older than `TRIP_RETENTION_DAYS` are deleted per `company_id` via `vehicles` (no `company_id` on `trips`). `0` disables prune. Raw telemetry stays `TELEMETRY_KEEP_PER_VEHICLE`.
- Geometry helpers (`haversineMeters`, `pathLengthMeters`, `simplifyPath`) live in `lib/geo.ts`. Models must not import from `sim/`.
- The simulator lives in `sim/routes.ts`. Kinematics use the real seconds since a vehicle's last ping (`elapsedS`, default `SIM_PING_SECONDS` in tests), never `config.telemetryTickMs` (that is `0` in tests). Pause/resume is `GET`/`PATCH /api/sim` per session company; `PATCH` requires `dispatcher`. It does not change vehicle status and does not pause other companies.
- Wall-clock trip duration is meaningless while `TIME_SCALE` compresses time. Do not derive an average speed from it.

## Dev data

- `apps/api/data/fleetlive.db` holds demo data grown over time (imports, scripts; thousands of vehicles). `npm run db:seed` replaces it with the small seed and cannot bring it back. A hook blocks the seed; only after the user asks for a reseed, back up `fleetlive.db*` and prefix the command with `ALLOW_SEED=1`.
- Fix wrong data in place with SQL after copying `fleetlive.db*` to a backup folder. The API keeps the file open; restoring means copying tables back with `ATTACH`, not replacing the file.
- `npm run db:repair-data` (`--dry-run`, `--company-id`; `db/repairData.ts`) repairs states the rules forbid in data that already exists; see architecture.md (Domain rules). New data (seeds, import, migration) must not create them: add a check to `demoDataInvariants.test.ts` when a rule is added. Back up first with the SQLite backup API (`backup()` from `node:sqlite`), a plain file copy fails while the API holds the `-shm`. Run it dry first and read the counts.
- Never stop a terminal tab the user started (their `npm run dev`); work around it.

## After changes

- Broadcast `vehicles-changed` after vehicle mutations, scoped to the session company.
- Run `npm test`.
